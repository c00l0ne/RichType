# Состояние проверок

[На главную](../README.md)

Эта страница описывает завершённые проверки исходного проекта Kazrich, получившего название RichType. Здесь приведены результаты сохранённой сводки разработки; при подготовке репозитория тесты не запускались.

## Версии

| Версия | Изменения | Подтверждение |
|---|---|---|
| 0.8.31 | Контекст для коротких слов и неоднозначных буквенных клавиш | Завершены перечисленные ниже проверки |
| 0.8.32 | Продолжение слова после паузы за дефисом, например `bp-за` | Код изменён, сборка выполнена; новых прогонов нет |
| 0.8.33 | Сохранение очереди при переключении языка | Код изменён, сборка выполнена; новых прогонов нет |
| Публикация RichType | Название интерфейса и сборки, документация, очистка комплекта исходников | Сборка RichType и проверка состава публикации; без повторного тестового набора |

Исходная версия 0.8.33 была установлена и запущена. Это подтверждает запуск приложения, но не является отдельным воспроизведением дефектов переключения языка.

## Последний завершённый набор: 0.8.31

| Набор | Успешно / всего |
|---|---:|
| Проверки логики | 689 / 689 |
| Модельные случаи на GPU | 1647 / 1647 |
| Новые модельные случаи на CPU | 36 / 36 |
| Сценарии ввода и исправления примеров | 32 / 32 |
| Прежние сценарии ввода | 100 / 100 |
| Изменения поля во время чтения | 46 / 46 |
| Отдельные поля Chrome | 27 / 27 |

Все 36 новых модельных результатов совпали на CPU и GPU. Повторная обработка результатов новых случаев не меняла текст. В проверках ввода рассматривались разные интервалы между клавишами, паузы внутри фразы, сохранение предыдущего абзаца и позиции курсора, отмена замены.

Проверки Chrome охватывали обычные поля, многострочные поля, `contenteditable`, парольные поля и поля только для чтения. Наличие этих проверок не означает поддержку всех сайтов и редакторов Chrome.

## Предыдущий большой набор

В более ранней завершённой проверке прошли **587 проверок логики** и **1547 модельных случаев отдельно на CPU и GPU**. Это другой исторический набор; его нельзя складывать с результатами 0.8.31 и называть количеством уникальных проверок текущей версии.

## Как трактовать цифры

- Результаты относятся к определённым версиям, конфигурациям и конечным наборам примеров.
- Успешный набор не доказывает отсутствие ошибок на произвольном тексте.
- Изменения 0.8.32–0.8.33 не покрыты новым завершённым прогоном.
- Сборка, запуск программы и тестирование её поведения — разные подтверждения.

Исходники проверок лежат в `tests`. Скрипт `build.cmd` только собирает приложение. Тесты запускаются отдельно, например `test.cmd` для логики; интерфейсные и модельные сценарии требуют соответствующей среды и могут занимать значительное время.
